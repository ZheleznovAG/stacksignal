# Руководство пользователя StackSignal

[Документация](README.md) · [Установка и эксплуатация](OPERATIONS.md)

StackSignal связывает найденные технологии с задачами ваших проектов и сохраняет
проверки и решения. Назначение — [миссия](MISSION.md), текущее состояние — [STATUS.md](STATUS.md),
установка/резервное копирование — [OPERATIONS.md](OPERATIONS.md).

## Quick start

Нужен Python 3.11+. Команды из корня одинаковы для поддерживаемых ОС:

```text
python stacksignal.py run
```

Откройте **http://localhost:8000**. Первая установка создаст `.venv` и установит
ограниченные версии зависимостей. Существующая `.env` сохраняется. Новая база пустая.

1. Откройте **Проекты → Сканировать папку**. Выберите папку с проектами, проверьте
   предложенные названия/описания/зависимости и импортируйте нужное.
2. Проверьте профиль: что строится, что уже используется, какую конкретную задачу нужно решить.
3. Нажмите **Собрать**. Время зависит от бюджетов источников и настроек AI.
4. В **Сегодня** и рабочем пространстве проекта изучите находки и причины соответствия.
5. В **Потребности** подготовьте проверку кандидата, передайте задание агенту и сохраните
   фактический результат со свидетельствами.

Сбор и ключевые слова работают без AI. При включённых эмбеддингах модель локального
смыслового поиска загружается при первом использовании. `EMBEDDINGS_ENABLED=0` отключает эту загрузку.

## Ежедневная работа

В **Сегодня** видны свежие подходящие находки, решения, требующие внимания, изменения
релизов/зависимостей и состояние последнего сбора. Смотрите не только на количество
материалов, но и на то, завершились ли нужные этапы и было ли AI-обогащение.

Ежедневный сбор назначен на 08:00 локального времени, пока приложение работает.
`DAILY_RUN_TIME` меняет время, `SCHEDULER_ENABLED=0` отключает расписание. Задержанное
задание работающего процесса может выполниться в пределах шестичасового окна; при
выключенном приложении автоматического исполнения за пропущенный день нет.

| Экран | Для чего нужен |

| **Проекты** | Контексты и их рабочие пространства |
| **Релевантное** в проекте | Находки с причинами соответствия; смотрите происхождение оценки |

| **Потребности** | Порядок задач, ограничения, критерии, кандидаты, задания и результаты проверок |
| **Решения** | Что оценить, попробовать, использовать, наблюдать, отложить или отклонить; история и пересмотр |

Карточка находки открывает содержание, показатели, релизы, возможности, связи с другими
источниками, соответствие проектам, заметки, решения и историю.

## Проекты и потребности

Описание и существующий стек — основной источник персонализации. Тип контекста,
жизненный цикл и включение поиска задаются отдельно. Архивный контекст сохраняет историю.
Сканирование читает поддерживаемые README, манифесты и lock-файлы в пределах ограничений
глубины/размера; предложения сохраняются после проверки пользователем.

При настроенном AI **Переосмыслить проект** строит техническую модель и выводит
потребности из реальных пробелов. Ручные требования остаются отдельными данными.
Изменение профиля может сделать модель устаревшей. Зависимая задача готова только
после подтверждённого актуального результата предварительной потребности.

В карточке потребности заданы ограничения и критерий проверки. Кандидат по словам,
AI-оценка применимости и выполненный опыт отображаются отдельно. Выберите небольшой
пилот — до трёх потребностей на проект, девяти суммарно — для ограниченного анализа.
Кнопка оценки обрабатывает очередной пакет именно открытого проекта.

## От кандидата к результату

1. Раскройте кандидатов и нажмите **Подготовить проверку**. Сохраняются профиль,
   требования, кандидат/источник и имеющаяся оценка на момент подготовки.
2. Скопируйте **Задание для Claude** или скачайте `.md`. Передайте его своему агенту
   в папке нужного проекта; выполнение запускается в среде агента.
3. **Начать проверку** отмечает работу. Противоречие актуальным ограничениям и
   незакрытые предварительные задачи препятствуют началу нового опыта.
4. **Записать результат** сохраняет итог, описание и свидетельства: измерения,
   воспроизводимые команды, ссылки или пути к отчётам. Для «Полезно» и «Не подошло»
   нужно хотя бы одно свидетельство; невозможность проверки обозначается отдельно.
5. При полезном результате можно явно подтвердить закрытие потребности. Решение
   по технологии для проекта задаётся отдельно либо сохраняется прежним.

Изменившиеся требования или содержание отмечают старый опыт как устаревший. Его
задание и итог сохраняются. Завершённый опыт неизменяем; повторная проверка создаёт
новую запись. AI-текст и подготовленное задание сами по себе не подтверждают полезность.

## Решения и обратная связь

Решение принадлежит паре «находка/проект»: оценить, пробовать, использовать, наблюдать,
отложить или отклонить. Можно записать цель, критерий успеха, итог и условие пересмотра.
Когда появились новые релизы/альтернативы, сервис показывает основания вернуться к решению.
Голоса помогают уточнять ранжирование; профиль проекта и его потребности работают без
обязательной ручной разметки большого каталога. История сохраняется после повторного анализа.

## Configuration

Настройки задаются через переменные процесса или `.env`, затем читается личная `.env`
из `STACKSIGNAL_PRIVATE_DIR`. После изменения перезапустите сервис. Полный пример —
[.env.example](../.env.example); технические параметры находятся в `backend/app/config.py`.

| Настройка | Значение / назначение |
| --- | --- |
| `STACKSIGNAL_PRIVATE_DIR` | Отдельная личная папка с `.env` и `data/`; по умолчанию runtime внутри checkout |
| `STACKSIGNAL_DATABASE_URL` | Явный URL файловой SQLite-базы; обычно менять не требуется |
| `GITHUB_TOKEN` | Необязательный доступ к public API с дополнительным бюджетом |
| `GITHUB_LOGIN` | Необязательное использование звёзд/подписок как источника находок и авторов |
| `AI_ENABLED` | `0` по умолчанию; `1` вместе с ключом включает внешний AI-шлюз |
| `AI_BASE_URL`, `AI_API_KEY` | Адрес и ключ отдельного шлюза; ключ не вставляется в URL |
| `GATEWAY_API_KEY` | Явный alias из окружения/`.env`, если основной ключ пустой и URL стандартный; чтения реестра нет |
| `AI_TIMEOUT`, `AI_REQUEST_TIMEOUT_MS` | Клиентский и передаваемый шлюзу бюджет времени |
| `AI_MAX_CALLS_PER_RUN`, `AI_BATCH_SIZE` | Ограничение реальных AI-вызовов и размера пакета |
| `AI_TEXT_LANG` | Язык генерируемых пояснений, по умолчанию `ru` |
| `EMBEDDINGS_ENABLED` | `1` по умолчанию; локальная модель семантического поиска, скачиваемая при первом использовании |
| `SCHEDULER_ENABLED`, `DAILY_RUN_TIME` | Расписание сбора, по умолчанию включено в 08:00 |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Необязательная доставка дайджеста настроенному чату |
| `DIGEST_ENABLED`, `DIGEST_LANG` | Включение и язык дайджеста; без настроенного бота отправки нет |
| `TELEGRAM_PROXY` | Необязательный proxy для Telegram |

## The AI gateway

Шлюз запускается отдельно и не входит в репозиторий. Клиент использует HTTP(S),
`Authorization: Bearer ...` и idempotency key. Требуется собственный контракт:

- `GET /v1/profiles`: сведения маршрутизации с `routing_version`.
- `GET /readyz`: `ready` и `code`; необязательный `dispatch` сообщает паузу/интервал допуска.
- `POST /v1/generate`: выполнение структурированного задания с профилем и сообщениями.
- `GET /v1/responses/{id}`: опрос задания со статусом `queued`/`running`; завершённый
  ответ содержит `status: completed` и массив `output`.

Источники точного контракта — `backend/app/ai_client.py`, `ai_analysis.py` и их fake-тесты.
Произвольный URL model API требует адаптера к этому контракту. Сетевые ошибки, таймаут,
пауза и неопределённый исход различаются; сервис не должен считать недоступный AI
успешно выполненным анализом. Альтернатива — экспорт/применение локальным агентом
из [AGENT-WORKFLOWS.md](AGENT-WORKFLOWS.md).

## Data and privacy

База, профили с абсолютными путями, решения, пакеты агентов, AI-ответы, модели, логи
и backup — личное состояние. По умолчанию оно в игнорируемой `data/`; его можно вынести
через `STACKSIGNAL_PRIVATE_DIR` при остановленном приложении. Корневая `.env` может
содержать только указатель на эту папку. Настройка сама существующие файлы не переносит.

При анализе профили и выбранное содержание получают настроенный шлюз или агент.
Коллекторы обращаются к API источников; Telegram отправляет сообщения при настройке
доставки. Для issue/публичного примера используйте вымышленные данные.

```text
python stacksignal.py backup
python scripts/public_release.py --check
```

Полное восстановление требует также личных файлов и настроек: см. [OPERATIONS.md](OPERATIONS.md).
`scripts/make_archive.py` предназначен для приватного переноса исходного кода с историей;
такой архив не публикуется как release. Чистая публичная поставка — [public-release.md](public-release.md).

## Development

Для изменений кода начните с [AGENTS.md](../AGENTS.md), [CONTRIBUTING.md](../CONTRIBUTING.md)

```text
python stacksignal.py test
python stacksignal.py setup --browser
python stacksignal.py test --browser
```

Точка продолжения и незавершённые направления — [STATUS.md](STATUS.md).
