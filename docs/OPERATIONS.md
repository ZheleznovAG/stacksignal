# Установка и эксплуатация

## Единый запуск

Нужен Python 3.11+ с `venv` и `pip`. Во всех примерах `python` означает этот интерпретатор;
на системах, где он называется `python3`, используйте `python3`. Команды из корня проекта:

```text
python stacksignal.py setup
python stacksignal.py run
```

`run` выполняет первоначальную настройку автоматически. Зависимости ограничены
`backend/constraints.txt`; повторный запуск при неизменных файлах зависимостей не запускает
pip. Отпечатки для runtime/dev/browser хранятся в игнорируемой `.venv` и учитывают версию Python.
Обновить среду принудительно: `python stacksignal.py setup --force`.

Поведение виртуального окружения описано в документации Python [venv](https://docs.python.org/3/library/venv.html).

Активация виртуального окружения не требуется. Из другой папки можно вызвать абсолютный
путь к `stacksignal.py`; рабочая папка дочерних служебных команд устанавливается в корень
репозитория. Явно заданный путь резервной копии разрешается относительно папки вызывающего процесса.

Адрес по умолчанию — **http://localhost:8000**. Для другого порта:

```text
python stacksignal.py run --port 8123
```

Запуск привязан к loopback. Остановить интерактивный процесс — `Ctrl+C`.
Для разработки доступен `run --reload`. Режим с несколькими workers не предусмотрен:
расписание и блокировка сбора рассчитаны на один процесс.

## Диагностика

```text
python stacksignal.py doctor
python stacksignal.py exec -- -m pip check
```

`doctor` сообщает версии основных пакетов, фактический путь базы, место runtime,
результат SQLite `quick_check`/`foreign_key_check` и соответствие схемы текущей миграции.
Он не вызывает источники, AI, Telegram и не скачивает модель эмбеддингов. Отсутствующая
база до первого запуска обозначается как `not_created`; схема создаётся при старте сервиса.
При ошибке или несовпадении существующей схемы команда возвращает ненулевой код.
Пути в диагностике относятся к личной установке: проверяйте их перед публикацией отчёта.

API `/api/health` проверяет приложение и при настроенном AI может проверить готовность
шлюза. Это отдельная проверка от файловой диагностики `doctor`.

## Личное состояние

Настройки читаются в порядке: переменные процесса, корневая `.env`, затем личная `.env`.
Ни один существующий `.env` установка не перезаписывает. Чтобы вынести состояние,
укажите `STACKSIGNAL_PRIVATE_DIR` в переменных процесса или корневой `.env`.
Эта отдельная папка содержит `.env`, `data/`, базу, пакеты агентов и резервные копии.

Меняйте расположение при остановленном приложении. Настройка выбирает путь и не переносит
существующие файлы автоматически. Храните личную папку вне репозиториев. Перенос описан
в [usage.md](usage.md#data-and-privacy); правила публикации — [public-release.md](public-release.md).

`STACKSIGNAL_DATABASE_URL` явно выбирает файловую SQLite-базу. Диагностика и backup
используют этот же путь. Относительные SQLite URL разрешаются в рабочей папке процесса;
через единый запуск это корень проекта. Для эксплуатации предпочтителен абсолютный путь.
In-memory базы и специальные SQLite URI не поддерживаются этими файловыми служебными командами.

## Резервное копирование и восстановление

```text
python stacksignal.py backup
python stacksignal.py backup path/to/new-snapshot.db
```

Создаётся согласованный SQLite-снимок, включая подтверждённые записи WAL, с проверкой
целостности. Существующий файл и путь исходной базы в качестве назначения отклоняются.
По умолчанию новый снимок попадает в настроенную `data/backups/`.
Используется стандартный [SQLite backup API Python](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup).

Для полного восстановления дополнительно сохраните личную `.env`, профили и результаты
агентов из личной папки. Команда backup копирует только базу. Порядок восстановления:

1. Остановить единственный процесс StackSignal и убедиться, что он завершился.
2. Сохранить отдельную копию текущего состояния перед заменой.
3. Восстановить снимок именно по пути базы, показанному `doctor`. Убрать старые WAL/SHM
   sidecar-файлы этой базы, оставшиеся от прежнего экземпляра; не смешивать их со снимком.
4. Восстановить нужные настройки и остальные личные файлы, затем запустить сервис.
5. Выполнить `doctor` и проверить проекты/решения в интерфейсе.

## Автозапуск и журналы

Перезапуск процесса и запуск при входе пользователя — зона штатного менеджера ОС.
Общая команда во всех случаях:

```text
python /absolute/path/to/StackSignal/stacksignal.py run --log-file /absolute/path/to/private-state/data/logs/server.log
```

Используйте абсолютные пути к установленному Python и скрипту. Сначала выполните
`setup` в обычном терминале и проверьте `doctor`. `--log-file` добавляет stdout/stderr
сервера в указанный файл; ротацию настраивает внешний менеджер журналов.

| Среда | Настройка вне исходного кода |
| --- | --- |
| Windows | Планировщик заданий: вход пользователя, действие — Python/`pythonw` и общая команда, одна активная копия, повтор при ошибке. При миграции старой установки замените прежнее действие, ссылающееся на удалённый launcher. |
| Linux | Пользовательский service manager, например systemd: абсолютный `ExecStart`, один процесс, повтор при сбое; stdout можно направить в его журнал. |
| macOS | Пользовательский LaunchAgent: список аргументов общей команды, заданные пути stdout/stderr и политика перезапуска. |

Общие Python-команды не устанавливают и не изменяют системные службы, реестр или
планировщик ОС. Перенос репозитория требует обновить абсолютный путь в своей службе.
Статус автозапуска проверяется в менеджере ОС; наличие listening port само по себе не
подтверждает, что нужное приложение здорово.

## Обновление

1. Сохранить базу и личные файлы; проверить рабочее дерево перед обновлением исходного кода.
2. Остановить сервис, обновить исходный код и выполнить `python stacksignal.py setup`.
3. Запустить сервис: Alembic обновит схему автоматически.
4. Выполнить `doctor` и открыть интерфейс. При ошибке миграции сначала сохранить логи
   и состояние, затем восстанавливать согласованный снимок вместе с соответствующей версией кода.

Сервис локальный и без аутентификации. Публикация исходного кода на GitHub не означает
готовность выставить работающий сервер в интернет; сетевой режим требует отдельного проектирования.
